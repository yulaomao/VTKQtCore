# VTKQtCore 项目总览与索引

## 文档定位

本套文档服务两类核心读者：

- 新加入项目的开发者
- 需要在其他平台、其他语言中复刻本系统的实现团队

本文档包以当前仓库代码行为为唯一真相基线。已有设计文档仅用于解释设计意图，不覆盖当前代码已经表现出的事实。

本文档的目标不是介绍代码目录，而是冻结以下内容：

- 公开协议字段名、枚举值、固定字符串
- 模块注册名、页面名、功能名
- 启动、装配、消息流转、模块切换、场景刷新等关键行为
- 跨语言重写时必须保持一致的命名与行为边界

## 一致性规则

### 第一层：必须完全一致

- Socket envelope 字段名
- AppMessage、UiAction、LogicNotification、ModuleInvoke、StateSample 的公开字段名
- 固定字符串，如 global、shell、global-ui、dispatch_module_ui_event
- moduleId、公开事件名、页面与功能名

### 第二层：应尽量一致

- 公开类名
- 公开函数名
- 公开状态名
- 对外暴露的概念命名

### 第三层：采用规范映射

- 私有成员
- 内部缓存结构
- 目标语言特有的资源管理、线程模型、UI 框架适配方式

## 项目总览

VTKQtCore 是一个 Qt + VTK + 可选 socket 兼容驱动的模块化客户端系统。它的稳定核心不在 UI，而在以下组合：

- 启动与装配层：决定启用哪些模块、页面顺序、初始模块和壳层扩展
- 通信层：兼容旧的 Socket JSON envelope，并在 socket 模式下提供可选入站/出站适配
- 运行时层：负责直接模块路由、模块切换、连接状态、错误事件和模块间调用
- 模块逻辑层：按模块处理业务输入、更新 SceneGraph、发出 LogicNotification
- 场景与显示层：SceneGraph 保存场景真相，DisplayManager 与 VtkSceneWindow 负责渲染同步
- UI 与 Shell 层：负责布局、控件、页面切换、全局提示和用户动作采集

## 分层结构

```mermaid
flowchart TD
		A[main.cpp] --> B[BaseSoftwareInitializer]
		B --> C[ApplicationCoordinator]
		B --> D[PageManager / GlobalUiManager]
		B --> E[LogicRuntime]
		B --> F[CommunicationHub (Socket 模式可选)]
		F --> E
		E --> H[ModuleLogicRegistry]
		H --> I[ModuleLogicHandler]
		I --> J[SceneGraph]
		J --> K[VtkSceneWindow / DisplayManager]
		C --> L[ModuleCoordinator]
		L --> M[Page Widgets]
		M --> N[UiActionDispatcher]
		N --> E
```

## 运行主链路

### 主链路一：Socket 数据进入系统

```text
Socket JSON envelope
	-> CommunicationHub
	-> LegacySocketAdapter / MessageRouter
	-> LogicRuntime
	-> ModuleLogicHandler
	-> SceneGraph
	-> LogicNotification
	-> ApplicationCoordinator / ModuleCoordinator / Page
	-> VtkSceneWindow reconcile
```

### 主链路二：UI 动作进入系统

```text
Widget / Page
	-> UiActionDispatcher
	-> ILogicRuntimePort(LogicRuntime)
	-> LogicRuntime::onActionReceived()
	-> ModuleLogicHandler
	-> LogicNotification / SceneGraph 变更 / 外发命令

Socket 模式下，UiActionDispatcher 发出的 action / resync 会被额外镜像到 CommunicationHub，但本地 UI 主路径不再依赖 loopback。
```

### 主链路三：模块切换

```text
UiActionDispatcher::requestModuleSwitch()
	-> LogicRuntime::switchToModule()
	-> ActiveModuleState 更新
	-> ModuleChanged / ActiveModuleChanged 通知
	-> ApplicationCoordinator::setCurrentModule()
	-> PageManager 切页 + 挂载辅助面板
```

## 模块地图

### 主业务模块

| moduleId | 角色 | 当前页面/窗口特征 |
| --- | --- | --- |
| datagen | 数据与场景节点生成 | 主页面 + 单 VTK 窗口 |
| params | 参数维护 | 主页面 + 右侧摘要面板 |
| pointpick | 点选与确认 | 主页面 + 右侧状态面板 |
| planning | 规划状态与 3D 视图 | 主页面 + 双 VTK 窗口 + 右侧摘要 |
| navigation | 导航状态与位姿显示 | 主页面 + 单 VTK 窗口 + 右侧摘要 |

### 辅助模块

| moduleId | 角色 | 说明 |
| --- | --- | --- |
| intermoduletest | 跨模块事件测试 | 用于验证模块间发送和接收 |
| workflowshell | 壳层相关模块集合 | 包含模块导航、状态栏等壳层能力 |

## 关键固定名词

| 名词 | 固定写法 | 含义 |
| --- | --- | --- |
| 广播目标 | global | 面向所有模块的目标域 |
| 壳层目标 | shell | 面向壳层 UI 的目标域 |
| 全局 UI 目标 | global-ui | 面向全局 UI 服务的目标域 |
| 模块 UI 事件命令 | dispatch_module_ui_event | 跨模块 UI 意图的固定命令名 |
| 轮询进度提示音 | polling_progress | 轮询进度音频预设 |
| 轮询注意提示音 | polling_attention | 轮询注意音频预设 |

## 术语表

| 术语 | 含义 |
| --- | --- |
| SoftwareInitializer | 软件装配器，负责把模块、页面、壳层、通信源组装成完整软件 |
| ApplicationCoordinator | 全局 UI 协调器，负责模块切换和全局通知接入 |
| ModuleCoordinator | 单模块 UI 协调器，负责模块页面和辅助面板生命周期 |
| ILogicRuntimePort | UI 到运行时的最小边界，只负责发送动作和请求重同步 |
| ModuleLogicHandler | 模块业务逻辑处理器 |
| SceneGraph | 场景数据真相层 |
| VtkSceneWindow | 场景显示窗口，负责根据 SceneGraph 重建显示状态 |
| LogicNotification | 逻辑层发往 UI/Shell 的统一通知对象 |
